# Как проверять Curie

## Без телефона (работает уже сейчас)

```powershell
cd app
flutter analyze          # статический анализ
flutter test             # логика конфига, профилей, локализация, экран
flutter build apk --debug
```

Это ловит почти всё, кроме собственно туннеля: сборку Kotlin, манифест, линковку
`libXray.aar`, вёрстку и обе локали.

## Эмулятор

На этой машине виртуализация в BIOS уже включена
(`VirtualizationFirmwareEnabled = True`), AVD `Medium_Phone_API_37.0` и образ
`android-37.0/google_apis_playstore/x86_64` установлены. Пакет драйвера
`Android_Emulator_Hypervisor_Driver` скачан в SDK, но сам драйвер ещё не установлен:
`emulator -accel-check` сообщает, что ускорения нет. Образ x86_64 **не запускается без
ускорения** — флаг `-no-accel` эмулятор 37.x уже игнорирует.

Одноразовая настройка (PowerShell **от имени администратора**, затем перезагрузка):

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\extras\google\Android_Emulator_Hypervisor_Driver\silent_install.bat"
```

Проверить:

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\emulator\emulator.exe" -accel-check
```

Если ускорение всё ещё недоступно из-за включённого Hyper-V/WSL2, включите компонент
Windows «Платформа гипервизора Windows» (Hypervisor Platform) и перезагрузитесь —
эмулятор воспользуется WHPX вместо AEHD.

Запуск готового AVD и установка APK:

```powershell
$sdk = "$env:LOCALAPPDATA\Android\Sdk"
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
& "$sdk\emulator\emulator.exe" -avd Medium_Phone_API_37.0 -no-boot-anim -no-snapshot
```

Во втором окне PowerShell:

```powershell
$sdk = "$env:LOCALAPPDATA\Android\Sdk"
$adb = "$sdk\platform-tools\adb.exe"
& $adb wait-for-device
& $adb shell 'while [ "$(getprop sys.boot_completed)" != "1" ]; do sleep 2; done'
& $adb install -r "C:\Users\Dmitrii\dev\curie\app\build\app\outputs\flutter-apk\app-release.apk"
# Важно: install -r не перезапускает уже открытое приложение — иначе экран останется старым.
& $adb shell am force-stop io.github.waylandx11.curie
& $adb shell am start -n io.github.waylandx11.curie/.MainActivity
```

Проверить, что установлена именно новая сборка:

```powershell
& $adb shell dumpsys package io.github.waylandx11.curie | Select-String versionCode,versionName
```

`-gpu swiftshader_indirect` добавляйте, если работаете через удалённый рабочий стол:
там нет нормального GPU. Когда эмулятор виден в `flutter devices`, вместо adb можно
запускать `cd app; flutter run`.

## Тестовый сервер без провайдера

Чтобы проверить туннель, не имея подписки, поднимается локальный Xray:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\dev-server.ps1
```

Скрипт качает официальный Xray-core для Windows в `tools/dev-server/`, слушает
`127.0.0.1:10086` (Shadowsocks, без TLS — только для разработки) и печатает ссылку:

```
ss://YWVzLTI1Ni1nY206Y3VyaWUtZGV2LXBhc3N3b3Jk@10.0.2.2:10086#CurieDev
```

`10.0.2.2` — это хост с точки зрения эмулятора. Вставьте ссылку в Curie, нажмите
«Подключить» и откройте в эмуляторе любой сайт: трафик должен пройти через сервер.
На реальном телефоне этот адрес не работает — там нужен настоящий сервер.

## Реальный телефон

1. Включить «Для разработчиков» → «Отладка по USB», подключить кабелем.
2. `flutter devices` — телефон должен появиться.
3. `cd app; flutter run` (или поставить собранный APK).
4. Вставить ссылку от провайдера, подключиться, проверить IP на любом «what is my ip».

Что смотреть в первую очередь: приходит ли уведомление, переживает ли туннель
смену Wi-Fi/LTE, отключается ли по кнопке в уведомлении.

## Чек-лист первой живой проверки

Подписки:

- [ ] подписка Remnawave добавляется по URL, узлы появляются списком;
- [ ] запрос идёт на `<ссылка>/json`, панель отдаёт JSON даже без правила (журнал: `XRAY_JSON`);
- [ ] если панель не понимает `/json`, клиент повторяет запрос по базовой ссылке;
- [ ] подписка с балансером подключается: обход российских сайтов и leastLoad работают;
- [ ] карточка провайдера сворачивается и разворачивается, видны трафик и объявление;
      развёрнутое состояние сохраняется после перезапуска приложения;
- [ ] в шапке карточки по порядку: название, обновление подписки, пинг, шестерёнка;
      длинное имя не перекрывается иконками;
- [ ] кнопка обновления показывает спиннер и подтягивает изменения;
- [ ] кнопка пинга показывает спиннер во время замера и обновляет миллисекунды у узлов;
- [ ] шестерёнка открывает меню только с копированием и отправкой ссылки и переходом
      в подписки; в скопированной/отправленной ссылке нет служебного `/json`;
- [ ] в нижней навигации только «Главная» и «Настройки», узлы доступны в карточке;
- [ ] время подключения и одна подпись «Скорость» находятся внутри большой кнопки,
      «Проверить» — в шапке рядом с темой и журналом, под кнопкой остаётся только имя узла;
- [ ] во время загрузки страницы/видео «Скорость» показывает ненулевое суммарное значение,
      в простое строка исчезает, стрелок ↑/↓ нет;
- [ ] после сворачивания на 10+ минут и возврата приложение показывает тот же туннель,
      время подключения не начинается заново и скорость снова обновляется;
- [ ] после свайпа приложения из «недавних» уведомление и туннель остаются, сеть работает;
- [ ] если сервер перестал отвечать, сторож через локальный прокси обнаруживает это
      и перезапускает ядро, не разрывая TUN (по записи в журнале);
- [ ] если ядро после сбоя не поднялось, туннель гаснет и на главной появляется ошибка,
      а не вечный «подключено»;
- [ ] смена узла во время подключения не создаёт второй параллельный коннект.
- [ ] долгое нажатие на узел открывает JSON/ссылку, правка сохраняется и остаётся после
      обновления подписки;
- [ ] доменные правила из JSON панели (`domain:`, `full:`, `regexp:`) работают: белые
      сайты идут напрямую, остальные — через прокси; CIDR-правила `ip:` тоже отправляют
      напрямую, а catch-all балансировщик их не перехватывает;
- [ ] пинг TCP и через прокси (режимы «По умолчанию», Double, keepAlive) дают миллисекунды, «n/a» у мёртвых узлов; ICMP в настройках отсутствует;
- [ ] узел-балансировщик с мёртвым основным сервером показывает задержку живого запасного, а не «n/a»; пока основной жив, показывается его задержка;
- [ ] конфиг Remnawave с `proxy` (fallback) и `proxy-2` (основной) подключается: при доступном `proxy-2` трафик идёт через него, при недоступном — через `proxy`; DNS и «Проверить» тоже идут через основной;
- [ ] во время замера у каждого измеряемого узла крутится спиннер, значения появляются по мере готовности, а не все сразу;
- [ ] настройки пинга: тип, режим, тайм-аут 5–15 сек и тестовый URL сохраняются после перезапуска; пояснительных подписей под выбором типа нет;
- [ ] при поднятом туннеле пинг через прокси работает (отдельный процесс `:ping`) и не переключается на TCP;
- [ ] TCP-пинг узла, у которого провайдер режет TLS/SNI, показывает «n/a», даже если порт открыт;
- [ ] флаги стран определяются по имени узла;
- [ ] таймер идёт при подключении и сбрасывается при отключении, но не сбрасывается
      при долгом фоне;
- [ ] при передаче данных меняется одна строка «Скорость», в простое она скрывается;
- [ ] кнопка «Проверить» видна только при подключении: при успехе — зелёный текст с
      миллисекундами, при обрыве — понятная ошибка;
- [ ] DNS по умолчанию «Из подписки»: серверы берутся из JSON панели; если их нет,
      используется резервный `77.88.8.8`;
- [ ] пункт «Свой» перекрывает DNS из подписки и сохраняется после перезапуска;
- [ ] переключатель «Резолвить DNS через туннель» убирает ошибки резолвинга на проблемных
      серверах;
- [ ] в карточке видны трафик, срок действия и реально настроенный интервал обновления;
      подсказка панели «Панель предлагает N ч» остаётся только в меню «Подключение»;
- [ ] подписка с истёкшим интервалом обновляется сама (журнал: `автообновление: … из …`),
      в том числе после возврата из долгого фона;
- [ ] в настройках «Интервал обновления, часы» задаётся числом 1–168 и перекрывает
      подсказку панели; при включённом туннеле обновление идёт через VPN (панель видит IP узла);
- [ ] «Обновить» подтягивает изменения с панели, «Обновить все» работает;
- [ ] после перезапуска приложения подписки и выбранный узел на месте;
- [ ] файл `curie-state.bin` в каталоге приложения нечитаем (шифр работает).

Раздельное туннелирование:

- [ ] «Все приложения через прокси» — IP меняется у всех;
- [ ] «Только выбранные» — IP меняется только у выбранных, у остальных прежний;
- [ ] «Выбранные идут напрямую» — наоборот;
- [ ] список приложений показывает названия и иконки, поиск работает;
- [ ] с «Показывать системные» виден Android Auto и другие приложения без иконки в лаунчере;
- [ ] смена режима требует переподключения и после него применяется.

Прочее:

- [ ] QR: навести на код из панели — сервер добавляется, камера закрывается;
- [ ] QR с адресом подписки — добавляется подписка, а не сервер;
- [ ] QR из картинки в галерее — код распознаётся, при отсутствии кода понятный текст;
- [ ] HWID включён по умолчанию: устройство появляется в карточке пользователя Remnawave,
      идентификатор имеет вид `XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX`;
- [ ] после ручного выключения HWID заголовки не уходят (проверить в логах панели) и не
      включаются снова после обновления приложения;
- [ ] лимит устройств: при превышении текст про лимит, а не «HTTP 404»;
- [ ] кнопки сброса HWID нет; ID одинаков после переустановки приложения и разный на двух телефонах;
      в настройках виден только переключатель — ни сам ID, ни «ещё не создан» не выводятся;
- [ ] в «Настройки → О приложении» только две строки с версиями: «Проверить обновления»
      с текущей версией приложения и «Ядро Xray / libXray» с версией ядра; отдельной
      строки «Версия приложения» и отдельного пункта libXray нет;
- [ ] «Проверить обновления» в настройках показывает спиннер, при отсутствии новой
      версии — «У вас последняя версия», при ошибке сети — понятный текст;
- [ ] если на GitHub есть более свежий релиз, диалог показывает версию и предлагает
      открыть страницу релиза и скачать единственный universal-APK;
- [ ] при включённом туннеле проверка обновлений работает и панель/GitHub видят IP узла,
      а не локального провайдера;
- [ ] фоновая проверка приходит раз в сутки: новая версия — баннером на главной, по нажатию
      открывается тот же диалог; баннер остаётся после перезапуска приложения;
- [ ] если релиз сообщает новую версию Xray, отдельный диалог «Обновлено ядро Xray»
      появляется один раз на версию ядра и не повторяется при следующих проверках;
- [ ] если версия Xray та же, только строка «Доступна версия …» без сообщения про ядро;
- [ ] меню настроек содержит «Маршрутизацию», «Подключение», «Оформление»,
      «Журналы» и «О приложении»; в «Маршрутизации» только режим и выбор приложений,
      в «Подключении» — подписки, HWID, пинг и карточка «Сеть» (DNS, DNS через
      туннель, локальная сеть, MTU); подпись под «Подключением» — «Обновление раз
      в N ч» или «Обновление вручную», а не «Вкл 1»; это своя группировка, не копия
      чужого экрана;
- [ ] в «Журналах» можно включить/выключить журнал Xray, выбрать уровень
      `debug/info/warning/error/выкл`, срок хранения в часах и открыть просмотр;
- [ ] просмотр журнала переключается между «Приложение» и «Ядро Xray», строки копируются,
      после переподключения в файле есть записи с выбранным уровнем;
- [ ] при поднятом туннеле кнопка очистки журнала Xray показывает подсказку отключиться,
      а после отключения файл очищается без ошибок;
- [ ] в «Настройки → О приложении → Лицензии» код Curie указан как
      Curie Source-Available License 1.0, а не MIT; у third-party — MIT/MPL/BSD-3;
- [ ] «Вставить из буфера» — ссылка, список ссылок и URL подписки различаются верно;
- [ ] отказ в доступе к камере показывает понятный текст, приложение не падает;
- [ ] смена Wi-Fi ↔ LTE не рвёт туннель надолго;
- [ ] при подключении в шторке есть постоянное уведомление и значок VPN; на Android 13+
      перед первым подключением спрашивается разрешение на уведомления;
- [ ] кнопка «Отключить» в уведомлении останавливает сервис;
- [ ] отзыв VPN-разрешения в настройках Android корректно завершает сессию;
- [ ] русский и английский интерфейс, переключение языка сохраняется;
- [ ] кнопка темы в шапке перебирает все семь палитр; «Ваниль» и «Розовая» — светлые темы,
      лишь слегка темнее исходных, не режут глаза; чипы в настройках выбирают конкретную
      тему, выбор сохраняется после перезапуска, текст во всех экранах читаем в каждой теме.
