# Настройка панели (Remnawave)

Curie принимает **оба** формата подписки: JSON и base64-список ссылок, но
запрашивает JSON явно — добавляет к ссылке суффикс `/json`. Это стандартный
способ Remnawave запросить `XRAY_JSON`, он работает с настройками панели по
умолчанию и не требует правила. Если панель не понимает суффикс, клиент сам
повторяет запрос по исходной ссылке.

Curie представляется так:

```
GET /<shortUuid>/json
User-Agent: Curie/26.11.23.1810
Accept: application/json, text/plain;q=0.9, */*;q=0.8
x-device-os: android
```

User-Agent нужен только для идентификации клиента: встроенный whitelist
Remnawave (`Happ`, `INCY`, `v2rayNG` и др.) не содержит Curie, поэтому без
суффикса панель ответила бы `XRAY_BASE64`.

## Правило для JSON (необязательно)

Если хочется отдавать JSON без суффикса — например, чтобы в журнале панели
запросы помечались как `XRAY_JSON`, — добавьте правило. В панели:
**Subscription → Response Rules → добавить правило**.

```json
{
  "name": "Curie",
  "enabled": true,
  "operator": "AND",
  "conditions": [
    {
      "caseSensitive": false,
      "headerName": "user-agent",
      "operator": "CONTAINS",
      "value": "curie"
    }
  ],
  "responseType": "XRAY_JSON",
  "responseModifications": {
    "subscriptionTemplate": "Xray-json"
  }
}
```

После этого в журнале панели запросы Curie будут видны как `XRAY_JSON`, рядом
с INCY и Happ.

## Что читает клиент из ответа

| Заголовок | Зачем |
|---|---|
| `content-type` | приоритет формата: `application/json` → JSON |
| `profile-title` | имя подписки (может быть `base64:`) |
| `profile-update-interval` | период автообновления, часы |
| `subscription-userinfo` | трафик и срок действия |
| `announce` | текст объявления в карточке провайдера |
| `support-url`, `profile-web-page-url` | метаданные панели (в интерфейсе кнопок нет) |
| `x-hwid-*` | лимит устройств: понятное сообщение вместо «HTTP 404» |

## HWID

Выключен по умолчанию. Если в панели включён HWID Device Limit, включите
переключатель в настройках Curie — иначе панель ответит 404. Идентификатор
привязан к телефону (HMAC из ANDROID_ID / identifierForVendor), поэтому не меняется
при обновлении и переустановке и не имеет кнопки сброса. На панель уходит только
подписанное значение, не сам аппаратный ID. Формат —
`6B625E5A-26FD-9875-E216-BBFB088FD1AE`.

## Маршрутизация и DNS из JSON

Curie сохраняет из ответа панели `routing` (включая `balancers` и правила `domain:` /
`full:` / `regexp:`), `observatory` и `burstObservatory`. Собственные `socks`/`http`
inbound'ы панели заменяются одним TUN-inbound'ом, поэтому:

- TUN включает сниффинг HTTP/TLS/QUIC с `routeOnly: false`: Xray видит домен и
  правила панели вроде «российские сайты напрямую», а `direct` открывает домен, а не
  IP из вышестоящего DNS. Если панель не задала `domainStrategy` и прислала `ip:`-правила,
  Curie ставит `IpIfNonMatch`, чтобы белые списки по CIDR тоже проверялись;
- по умолчанию Curie использует `77.88.8.8` — он доступен и через прокси, и напрямую
  и часто лежит в белых списках панели. Явно выбранный адрес важнее `dns.servers` из
  JSON: вернуть конфиг панели можно пунктом «Из подписки» в настройках DNS;
- выбранные DNS-серверы получают `tag` рабочего outbound'а, поэтому запросы не зависят
  от белых списков и провайдер не видит имена сайтов. Если UDP DNS через прокси не нужен,
  в настройках Curie есть переключатель «Резолвить DNS через туннель» — при выключении
  серверы получают `tag: direct`;
- адрес самого узла резолвится защищённым системным сокетом Kotlin, так что петли
  «DNS через туннель → туннель через DNS» не возникает.

Кнопка «Проверить» использует локальный HTTP-прокси на `127.0.0.1`, явно
прописанный в `network_security_config.xml`, и маршрутизирует его через рабочий
outbound. Проверка честно показывает доступность интернета именно через туннель.
