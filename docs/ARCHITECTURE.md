# Curie — архитектура

Документ описывает, как устроено приложение и почему именно так. Обновлять при каждом
существенном решении.

## Границы

Делаем **свой** клиент, а не форк. Причина — лицензии и стор:

- keqdroid распространяется под AGPL-3.0. Производное произведение остаётся AGPL навсегда,
  закрыть его нельзя, а App Store с AGPL несовместим.
- Поэтому берём только совместимые со стором компоненты: `libXray` (MIT), `Xray-core`
  (MPL-2.0), Flutter (BSD-3). Ни одного GPL/AGPL компонента в проекте нет.
- Собственный код распространяется под Curie Source-Available License 1.0 (`LICENSE`):
  репозиторий можно закрыть в любой момент. Снимки, опубликованные до смены лицензии,
  остались под MIT — новые версии уже под source-available лицензией.

| Слой | Технология |

| Состояние | `ValueNotifier` + `setState`; Riverpod подключим, когда экранов станет больше |

## Темы

Семь тем: фирменная тёмная (по умолчанию), светлая, янтарная, океан, лесная,
ваниль и розовая. «Ваниль» и «Розовая» — светлые палитры, лишь немного темнее
исходных: кремовый и розовый фон с приглушёнными акцентами.
Каждая строится из своего seed-цвета через `ColorScheme.fromSeed`; акценты и
«хороший» цвет успеха берутся из готовой `ThemeData` (`CurieColors`), поэтому
виджеты не привязаны к конкретной палитре. Старые значения `light`/`dark` в
`SharedPreferences` (`ThemeController`) мигрируют в новые идентификаторы без
сброса выбора пользователя; в шифрованном хранилище тема не лежит. Выбор —
чипы в настройках и быстрая кнопка в шапке главного экрана, перебирающая темы
по кругу.

## Android: путь одного подключения

Реализовано в `app/lib/src/services/*` и `app/android/.../CurieVpnService.kt`.

1. Пользователь вставляет ссылку (`vless://`, `vmess://`, `trojan://`, `ss://`).
2. Dart отдаёт её ядру: `convertShareLinksToXrayJson` возвращает `data.outbounds`. Свой парсер
   не пишем — ядро и так валидирует каждый outbound, а формат ссылок меняется вместе с ним.
   В хранилище лежит **ссылка**, а не готовый конфиг: при обновлении ядра профили не устаревают.
3. Dart собирает конфиг (`buildXrayConfig`): серверные outbound'ы, `freedom` (direct),
   `dns` (dns-out), `tun`-inbound со сниффингом, DNS-модуль и правила маршрутизации. Geo-файлы не нужны:
   приватные сети перечислены CIDR'ами.
4. Dart зовёт канал `io.github.waylandx11.curie/bridge`, метод `connect(config)`.
5. `MainActivity` запрашивает `POST_NOTIFICATIONS` (Android 13+, иначе уведомление и значок не видны),
затем `VpnService.prepare` и только после этого стартует сервис.
6. Сервис строит интерфейс: MTU из настроек, адреса `172.19.0.1/30` и `fdfe:dcba:9876::1/126`,
   DNS из подписки (или резервный `77.88.8.8`), маршруты `0.0.0.0/0` и `::/0`, свой пакет
   исключён из туннеля.
7. `LibXray.registerDialerController(controller)` — `protectFd` вызывает `VpnService.protect`,
   иначе соединение ядра к серверу попадёт в собственный TUN. `LibXray.setDNS(controller,
   "<dns>:53")` уводит Go-резолвер мимо туннеля.
8. Kotlin дописывает в корень конфига `env."xray.tun.fd"` (номер fd строкой) и вызывает
   `LibXray.invoke({"apiVersion":3,"method":"runXray","payload":{"xrayJson":"…"}})`.
   Ответ — `{"success":bool,"data":…,"error":"…"}`.
9. Статус пушем уходит в Dart (`stateChanged`), уведомление обновляется. Отключение —
   `stopXray`, `resetDNS`, закрытие fd, `stopSelf`.

Состояние живёт в `CurieBridge` (синглтон в процессе): статус, порты метрик и
локального `check`-прокси, время старта сессии. После перезапуска UI достаточно спросить
`status`, а не угадывать. Конфиг подключения дублируется в приватные `SharedPreferences`
шифротекстом (ключ — в Android Keystore): при `START_STICKY` (убийство процесса или нехватка
памяти) сервис поднимает туннель заново без Flutter. Команды нумеруются: устаревшая задача
из очереди не может стереть сохранённую сессию более новой команды. Сторож раз в 30 секунд
делает GET через локальный прокси и после двух неудач перезапускает только ядро, не трогая
TUN; если сети телефона нет, сбой не считается поломкой туннеля. Если перезапуск ядра не
удался, сервис гасит TUN и уходит в `error` — интерфейс не остаётся «подключённым» мёртвым
туннелем.

Почему так, а не как в keqdroid: они держат ядро отдельным процессом (`fork/exec` бинарника из
`jniLibs`), потому что им нужны две разные реализации ядра и смена версий. Нам это не нужно, а
цена — нативный лаунчер, передача fd через границу процесса и оркестрация сирот. Библиотека
в процессе решает то же самое меньшим кодом.

## Подписки

- Панель (Remnawave и совместимые) отдаёт **JSON или base64**. Curie явно просит JSON:
  добавляет к ссылке `/json` (стандартный суффикс Remnawave) и только если он не сработал —
  повторяет запрос по исходной ссылке. JSON разбирается первым, текст — как ссылки.
  User-Agent остаётся `Curie/…` (без имитации других клиентов): версия приложения и ядра
  берутся из `build_info`/`core_info`, версия ОС — через нативный `platformInfo`
  (`Android17`). Префикс `v` у версии ядра убирается, точный заголовок один раз пишется
  в `AppLog`. Настройка панели — в `docs/PANEL.md`.
- JSON понимается в трёх видах: массив конфигов с `remarks` (стандарт XTLS), полный конфиг
  с `routing`/`inbounds` (один узел) и «голый» объект `outbounds` (каждый прокси-протокол — узел).
  Узел хранится **как есть**, готовым JSON, и не пересобирается через ссылки.
- Полный конфиг панели сохраняется целиком: `routing.rules`, `routing.balancers`,
  `burstObservatory` и `dns`. Это обязательно для балансеров (`leastLoad`/`leastPing`) и обхода
  российских сайтов. При сборке заменяются только `inbounds` (вместо socks/http — TUN),
  добавляются правило DNS и метрики; `xray.tun.fd` подставляет Kotlin. По умолчанию DNS
  берётся из `dns.servers` подписки; фиксированный адрес (резервный `77.88.8.8`) используется,
  только если пользователь выбрал его в настройках или подписка не прислала DNS.
  У TUN-inbound обязательно задано
  `settings.name`: без него Xray вызывает `net.Interfaces()` для генерации utun-имени и
  падает на Android ошибкой `netlinkrib: permission denied`.
- Метаданные из заголовков: `profile-title`, `profile-update-interval`, `subscription-userinfo`,
  `announce`, `support-url`, `profile-web-page-url`. Кнопок «Сайт», «Поддержка» и перехода по
  названию подписки нет — ссылки пока никуда не ведут.
- Обновление — по таймеру раз в 15 минут и сразу при возврате в приложение; подписка
  считается устаревшей по числу часов из настроек (по умолчанию 1). Заголовок панели
  `profile-update-interval` хранится рядом с подпиской и показывается только как подсказка
  «Панель предлагает N ч» в меню «Подключение», но не перебивает ручной выбор. Карточка
  провайдера и список подписок показывают реально настроенный интервал. Есть также кнопка
  в карточке провайдера и «Обновить все».
  Все фоновые запросы идут через локальный HTTP-прокси Xray, когда туннель поднят,
  поэтому обновление не обходит VPN и работает при выключенном экране. Успех подтверждается
  сообщением и записью в журнал, ошибка — текстом в карточке и сообщением.
- Развёрнутость списка узлов и ручные правки узлов лежат в той же записи подписки, поэтому
  переживают и перезапуск, и обновление. Ссылка для буфера/«Поделиться» очищается от
  служебного `/json`, который Curie добавляет только к своему HTTP-запросу.
- Ошибки хранятся кодом (`http`, `hwidLimit`, `noNodes`, …), а не текстом: переводятся
  вместе с интерфейсом.

## Задержка узлов

Тип проверки выбирается в настройках: TCP или GET через прокси. ICMP убран —
на телефонах он ненадёжен, а старый выбор автоматически мигрирует в TCP.

| Тип | Что меряет |
|---|---|
| TCP | TCP-connect, а для TLS/REALITY — ещё и TLS-рукопожатие с настоящим SNI. Голый connect подтверждает только открытый порт и врёт, когда провайдер режет узел по имени |
| Через прокси (GET) | `pingBatch` ядра: GET-запрос через сам узел, полный путь (DNS, TCP, TLS) |

У узла-балансировщика проверяются основные outbound'ы (под селектором
`routing.balancers`) **и** запасной. В конфигах Remnawave первый хост имеет тег
`proxy` и работает как `fallbackTag`, а основные — `proxy-2`, `proxy-3`; Curie
определяет запасного по явному `fallbackTag` или по этому соглашению. Пока
основной отвечает, в списке его задержка; если основные мертвы — показывается
задержка запасного. Обычный узел без балансировки проверяется по одному
outbound'у.

Для подключения Xray получает балансировщик с `fallbackTag`: если панель его
не прислала, Curie добавляет `curie-auto-balancer` с селектором рабочих
серверов и запасным тегом, а также `burstObservatory` (иначе `leastLoad` не
запустится). Если панельный балансировщик есть, но `fallbackTag` не задан, он
добавляется к нему. DNS и локальная кнопка «Проверить» идут через основной
сервер, а не через первого в списке (которым часто оказывается запасной).

Режимы замера через прокси:

| Режим | Что делает |
|---|---|
| По умолчанию | один GET-запрос на новом соединении |
| Double | два независимых запроса, берётся лучший результат |
| keepAlive | два GET-запроса на одном соединении (`warm: true` ядра), замер чистого ответа без handshake |

Тайм-аут настраивается от 5 до 15 секунд и применяется ко всем типам; URL теста
по умолчанию `https://www.gstatic.com/generate_204` (Happ использует тот же адрес).

libXray держит один управляемый экземпляр и **запрещает `pingBatch`, пока в
процессе работает `runXray`**. Поэтому при поднятом туннеле запрос уходит в
отдельный процесс `:ping` (`PingService`): там второй, чистый libXray, и замер
через прокси работает без остановки VPN. `pingBatch` принимает не больше пяти
конфигов за вызов — список режется на пятёрки. Ответ ядра: `data.results` с
полями `success`, `delay` (`10000` — ошибка, `11000` — тайм-аут) и необязательным
`error`.

Результаты обновляются по мере готовности: у измеряемого узла крутится спиннер,
а миллисекунды появляются сразу после ответа его пятёрки, не дожидаясь всего
списка.

## Страна узла и время подключения

- Флаг берётся из имени узла: сначала эмодзи-флаг (панели кладут его почти всегда), затем
  словарь названий стран на русском и английском. Внешних запросов нет — IP никуда не уходят.
- Таймер берёт время старта из сессии нативного сервиса (`connectedAt`), поэтому после долгого
  фона не начинается заново. Опрос метрик тоже живёт вне экрана (`TunnelMonitor`): порт и
  время приходят из `CurieBridge`, а не из полей `HomeScreen`.
- В интерфейсе одна подпись «Скорость» с суммарным значением — стрелки ↑/↓ убраны, когда
  один из счётчиков подолгу держался нулевым. Сами счётчики берутся из ядра: в конфиг
  добавляются `metrics` (localhost, порт выделяется через `getFreePorts`), `stats` и политика
  `statsOutbound*`. Раз в секунду клиент читает `http://127.0.0.1:<port>/debug/vars` и считает
  разницу накопительных счётчиков; служебные outbound'ы `direct`/`block`/`dns-out` не
  учитываются. Это локальный запрос, он не идёт через туннель. При сбросе счётчиков или
  ошибке опроса последняя скорость обнуляется, а не висит на экране.

## Журналы

Два отдельных источника, переключаются на экране «Журнал»:

- `AppLog` — кольцо на 300 записей в памяти: подключения, ошибки ядра, обновления подписок.
  Никуда не отправляется. Первая запись при запуске содержит версию из `build_info`, поэтому
  журнал всегда показывает версию текущей сборки.
- Журнал Xray — приватный файл `curie-xray.log`, путь которого передаётся в конфиг как
  `log.error`. Ключ уровня — именно `logLevel` (`debug`/`info`/`warning`/`error`/`none`);
  старый `loglevel` ядро игнорировало. Включение, уровень и срок хранения (часы) задаются
  в настройках; `maskAddress` — строка `full` (булево значение ядро не примет), адреса
  маскируются полностью, доступ к файлу есть только у приложения. `CoreLog` читает файл,
  отбрасывает строки старше срока и ограничивает объём 2 МБ. Физическая очистка делается
  на старте приложения и при возврате в него, только если туннель не работает: перезаписывать
  файл, в который ядро ещё пишет, нельзя.

Оба журнала можно скопировать одним нажатием; очистка Xray-журнала доступна при отключённом
туннеле (иначе приложение просит сначала отключиться). Разбирать проблему можно без adb.

## HWID

- HWID **включён по умолчанию**: многие панели требуют его для лимита устройств. В настройках
  его можно выключить; после ручного выключения миграция его больше не включает. Сам ID и
  сообщения о его создании в интерфейсе не показываются — остаётся только переключатель.
  К запросу подписки добавляются `x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model`,
  `x-app-version`.
- `x-hwid` — **привязан к телефону**: HMAC-SHA256 из ANDROID_ID (Android, через
  метод channel `androidId`) или `identifierForVendor` (iOS), усечённый до 16 байт и
  отформатированный как UUID. Панель видит только подписанное значение формата
  `/^[a-zA-Z0-9=-]{10,64}$/`, не сам аппаратный ID. IMEI/серийные номера не читаются.
  Идентификатор стабилен при обновлении и переустановке, **кнопки сброса нет**.
  Кэш лежит в шифрованном хранилище; на устройстве без аппаратного ID используется
  сохранённое значение или случайный ID.
- Ответ панели разбирается: `x-hwid-max-devices-reached` / `x-hwid-limit` → «достигнут лимит
  устройств», `x-hwid-not-supported` и 404 без HWID → «панель требует идентификатор, включите
  HWID». Ошибки хранятся кодом, а не текстом, поэтому переводятся на язык интерфейса.

## Импорт серверов

Один вход (`showAddSheet`) на все способы: буфер обмена, QR-код, ручной ввод, подписка.
Дальше всё проходит через `Importer`:

- строка со схемой `vless/vmess/trojan/ss/socks/hysteria2/hy2` → сервер;
- `http(s)` с хостом → подписка;
- многострочный текст (например, скопированный список) → все найденные ссылки разом,
  дубликаты отбрасываются, битые пропускаются.

QR сканирует `mobile_scanner` (BSD-3, ML Kit на Android, AVFoundation на iOS). Разрешение
`CAMERA` и `uses-feature required=false` приезжают из манифеста плагина: приложение
ставится и на устройства без камеры. Буфер читаем через `Clipboard.getData` — на Android
это разрешено только активному приложению, отдельное разрешение не нужно.

QR можно взять и из картинки: `image_picker` даёт файл, `analyzeImage` разбирает его без
запуска камеры. На Android 13+ используется системный выбор фото — разрешение на доступ
ко всей галерее не требуется.

## Версии в интерфейсе

- Версия приложения — формат **YY.MM.DD.HHMM** (например `26.11.23.1810`), её ставит
  `scripts/set-version.ps1`: строка кладётся в `build_info.dart`, а в pubspec уходит
  `YY.MM.DD+<минуты с 2020>`. Код сборки обязан только расти, поэтому HHMM для него
  не годится — между сутками он уменьшается.
- Версия ядра — `xrayVersion` у работающего libXray, то есть правда о том, что в сборке.
- Версия обёртки — константа `libXrayVersion`, которую генерирует `scripts/sync-core.ps1`
  в `app/lib/src/generated/core_info.dart`. Руками её не правят.
- На главном экране короткая строка «Curie 0.1.0 · Xray 26.11.9», подробности — в настройках.

## Хранение: всё шифруется

- Состояние целиком (`AppState`: профили, подписки, настройки, выбранный узел) — один файл
  `curie-state.bin` в приватном каталоге приложения.
- Шифр AES-256-GCM, ключ случайный, лежит в Android Keystore / iOS Keychain через
  `flutter_secure_storage`. На диске нет ни ссылок, ни URL подписок открытым текстом.
- Запись атомарная: временный файл + rename, чтобы падение не оставило половину состояния.
- Язык интерфейса — единственное, что лежит в обычных настройках: это не секрет.

## Раздельное туннелирование (Android)

Три режима, ровно как в задаче:

| Режим | Что делает `VpnService.Builder` |
|---|---|
| Все приложения через прокси | свой пакет исключён, остальное в туннеле |
| Только выбранные через прокси | `addAllowedApplication` для каждого выбранного |
| Выбранные идут напрямую | `addDisallowedApplication` для каждого выбранного |

- Списки нельзя смешивать: Android бросит исключение, поэтому режимы взаимоисключающие.
- В режиме «только выбранные» своё приложение не добавляем — оно и так вне туннеля, петли нет.
- Если ни одно приложение из списка не подошло (удалено, скрыто), откатываемся к полному
  туннелю, а не оставляем пользователя без сети.
- Список приложений — `PackageManager.getInstalledApplications`: все установленные пакеты,
  включая системные и те, у которых нет иконки в лаунчере (Android Auto, GMS). Для этого
  объявлен `QUERY_ALL_PACKAGES`; без него Android 11+ отдаёт только лаунчерные приложения,
  и Android Auto в списке просто отсутствует. В Google Play разрешение требует декларации
  в Permissions Declaration Form — это надо заполнить при публикации.
- Пользовательские приложения идут первыми, системные скрыты за переключателем.
- Иконки отдаём лениво: `appIcon` по пакету, кеш в Dart. Список стал полным (сотни
  пакетов), отдавать все PNG сразу — лишние мегабайты и заметная задержка открытия.

## Сборка: что оказалось неочевидным

- Flutter 3.50 вынес Material в пакет `material_ui`; `package:flutter/material.dart` объявлен
  устаревшим. Локализация берётся из `GlobalMaterialLocalizations.delegates` того же пакета.
- Строки интерфейса — свой `AppLocalizations` без `gen-l10n`: кодогенерация тянет
  `flutter_localizations`, чьи делегаты относятся к старому Material и конфликтуют по типам.
- `cmdline-tools` Android Studio не ставит, а без них не работают ни лицензии, ни `flutter doctor`.
- Flutter требует NDK `28.2.13676358` и ставит его сам, но передаёт пакет как `ndk;<версия>`,
  а новый Android CLI понимает только `ndk/<версия>`. Поэтому NDK ставит `setup.ps1`.
- APK весит ~170 МБ, потому что несёт `libgojni.so` для трёх ABI. Собирается **один
  universal APK** (`flutter build apk`, без `--split-per-abi`): обновления ставятся поверх
  предыдущих сборок, а Play/стороны получают один и тот же артефакт. Shared debug-ключ
  подписи лежит в `app/android/app/debug.keystore` (не коммитится) и в CI — в секрете
  `CURIE_DEBUG_KEYSTORE_BASE64`; дайджест подписывающего сертификата одинаков локально и в CI.

## iOS: отличия

- Вместо `VpnService` — `NEPacketTunnelProvider`; TUN-дескриптор выдаёт система.
- Тот же приём: fd в `env."xray.tun.fd"`, затем `LibXray` через FFI.
- Память расширения ограничена (~50 МБ), поэтому конфиг и geo-данные держим компактными.
- Никакого скачивания исполняемого кода: только то, что вшито в бандл.

## Ядро и обновления

- `scripts/sync-core.ps1` берёт последний релиз `XTLS/libXray`, сверяет sha256 и кладёт
  `libXray.aar` в `app/android/app/libs/`. Версия и хеш — в `core.lock.json`.
- Новое ядро = новая версия приложения. В сторе это обычное обновление, отдельного механизма
  самообновления нет и не будет (в Play он запрещён, в App Store невозможен).
- Проверка обновлений смотрит публичные релизы GitHub раз в сутки (и по кнопке в настройках).
  При поднятом туннеле запрос идёт через локальный `check`-прокси — приложение исключено из
  собственного TUN, поэтому обычный Dart-HTTP обходил бы VPN. Версия ядра читается из текста
  релиза (`Xray-core: v…`, строка добавляется в `release.yml`); о новом ядре показывается
  отдельный диалог один раз на версию, обычная новая версия — только баннером на главной.
  Баннер переживает перезапуск: найденный релиз лежит в зашифрованном состоянии.
  «Скачать APK» просто открывает страницу/ассет во внешнем браузере, без установки из приложения.
- libXray совместим только с последним Xray-core. Это не ограничение, а правило: обновляемся
  вместе с ядром.

## Чего сознательно НЕ делаем

- **mihomo** и протоколы, которых нет в Xray (hysteria2, TUIC, WireGuard, AnyTLS). Если
  понадобится — это отдельное решение и отдельная лицензионная проверка (mihomo — GPL-3.0).
- **Выбор версии ядра** в UI. Версия одна, задаётся сборкой.
- **Свой апдейтер APK.** Обновления — только через сторы; проверка версии не ставит файлы сама.
- **Сбор статистики.** Ни аналитики, ни крэш-репортов по умолчанию. HWID провайдеру подписки
  включается по умолчанию (иначе лимит устройств у большинства панелей), но пользователь может
  выключить его в настройках; сам аппаратный ID никогда не отправляется.
