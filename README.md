# Curie

Curie — клиент Xray для Android (поддержка iOS планируется). Название — в честь Марии Кюри,
пионера исследований радиоактивности и рентгенографии.

Коротко о принципах:

- **Своё приложение, не форк.** Код пишется с нуля, без GPL/AGPL. Исходники доступны для
  изучения и личного использования под Curie Source-Available License 1.0; публикация и
  коммерческое использование требуют разрешения. Репозиторий можно закрыть в любой момент,
  не ломая лицензии зависимостей. Pub/App Store это не мешает.
- **Ядро вшито.** Xray-core попадает в сборку через официальную обёртку `libXray` (MIT). Новое ядро —
  новая версия приложения, дальше её развозят стора.
- **Ничего лишнего.** Ни mihomo, ни выбора версии ядра, ни собственного апдейтера. Всё это —
  источники багов, отказов на ревью и юридических вопросов.

## Состояние

Android-версия функционально готова к первой живой проверке:

- подписки по URL (Remnawave и совместимые): **JSON и base64**, включая конфиги с
  балансировщиком; трафик, срок действия, объявление панели и интервал обновления из
  заголовков панели. Интервал хранится вместе с подпиской и проверяется при каждом запуске;
  JSON запрашивается явно через `/json`, без правила в панели;
- карточка провайдера со списком узлов: флаг страны, протоколы, задержка в мс; состояние
  «развёрнут/свёрнут» сохраняется после перезапуска;
- замер задержки: TCP/TLS или GET через прокси (выбор в настройках);
- таймер подключения, скорость ↑/↓, флаг выходного узла и кнопка «Проверить» интернет
  через туннель на главном экране;
- два раздела: «Главная» и «Настройки» — список узлов развёрнут внутри карточки подписки;
- импорт: QR-код (камера или картинка из галереи), буфер обмена, ручной ввод;
  ссылки `vless://` / `vmess://` / `trojan://` / `ss://`;
- HWID для панелей с лимитом устройств — выключен по умолчанию, идентификатор случайный
  в формате `XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX` (старые значения мигрируют на месте);
- подключение, отключение, уведомление с кнопкой «Отключить» и постоянный значок VPN
  (на Android 13+ разрешение на уведомления запрашивается перед подключением);
- раздельное туннелирование: всё через прокси / только выбранные приложения / выбранные
  напрямую; в списке все установленные приложения, включая системные и Android Auto;
- настройки: DNS по умолчанию `77.88.8.8`, можно вернуть DNS из подписки или указать свой;
  резолвинг через туннель/напрямую, MTU, обход локальной сети, язык (русский и английский);
  версия приложения и версия Xray показываются вместе в шапке;
- меню по шестерёнке рядом с подпиской: копировать и «поделиться» ссылкой — служебный
  `/json` из неё убирается; долгое нажатие на узел открывает просмотр и правку конфига/ссылки
  (правки переживают обновление подписки);
- всё состояние шифруется: AES-256-GCM, ключ в Android Keystore.

Ядро `libXray v26.11.9` вшито в сборку. Сам туннель на устройстве ещё не проверялся —
см. `docs/TESTING.md`.

iOS — каркас Flutter без NetworkExtension, подключим позже.

## Структура

```
branding/            имя, идентификаторы, цвета, иконка
docs/                архитектура, как тестировать, настройка панели
scripts/             setup.ps1, sync-core.ps1, set-version.ps1, tag-release.ps1, dev-server.ps1
app/                 Flutter-приложение: Dart-UI и Kotlin-туннель
.github/workflows/   сборка в CI и публикация релизов по тэгу
core.lock.json       версия и хеш вшитого ядра
```

## С чего начать

```powershell
# 1. Окружение: Flutter, Android SDK, cmdline-tools, NDK, создание проекта
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1

# 2. Вшить ядро (скачает libXray.aar последнего релиза и проверит sha256)
powershell -ExecutionPolicy Bypass -File scripts\sync-core.ps1
```

Дальше — `cd app; flutter run`.

Требуется Android Studio (даёт JDK и Android SDK). Go не нужен: ядро приходит готовой
библиотекой. NDK нужен самой Flutter-сборке — `setup.ps1` ставит его сам, потому что
автоустановка из Flutter ломается на новом Android CLI.

Проверка без телефона: `flutter analyze`, `flutter test`, `flutter build apk --debug`.
Подробности и тестовый сервер — в `docs/TESTING.md`.

## Версии, GitHub и откат

Локальные подверсии тренируются без GitHub: `scripts\set-version.ps1` меняет штамп
сборки, APK собирается и ставится на телефон, но тэг **не создаётся**.

Публикация — отдельный осознанный шаг. Без `-Publish` скрипт только показывает,
какой тэг получился бы:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\set-version.ps1
powershell -ExecutionPolicy Bypass -File scripts\tag-release.ps1          # пробный запуск
powershell -ExecutionPolicy Bypass -File scripts\tag-release.ps1 -Publish -Push
git remote add origin https://github.com/WaylandX11/Curie.git
```

По push тэга `v*` workflow `.github/workflows/release.yml` прогоняет analyze/test и
прикрепляет к GitHub Release **четыре APK**: `universal`, `arm64`, `arm32`, `x64`
(плюс `.sha256` для каждого). Обычные push в `main` проверяет `build.yml`.

Приложение без Google Play проверяет релизы GitHub по кнопке «Настройки → О приложении →
Проверить обновления» и предлагает открыть страницу релиза или скачать APK под ABI
телефона. Старые релизы при этом не навязываются: сравнение идёт по штампу
`YY.MM.DD.HHMM`.

Откат — через тэг, без удаления истории: `git checkout -b rollback/<версия> <тэг>`.
Подробности и список версий — в `CHANGELOG.md`.
